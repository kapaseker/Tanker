# 玩家坦克模型契约

## 车型参考与还原范围

车型总览见 [坦克车型目录](tank-catalog.md)。当前玩家以 **Leopard 2A6（豹 2A6）及 L55 长炮管**为现实参考，采用 body/anvil、barrel/lance、track/cleat 组合；弹丸是 lance 的附属资源。

- **外观目标**：真实整车尺寸与比例、楔形炮塔、长炮管和抽烟器、装甲分区、分段裙板、车尾格栅、舱盖、简化观瞄、天线和车顶机枪；橄榄绿装甲、深灰履带、少量磨损。最终轮组为每侧七个负重轮与两个端轮。
- **选定美术参考**：[第一张整车概念图](references/leopard-2a6-concept.png)。该图指导体素风格与细节层次，轮数、尺寸和机械结构以对应型号可靠资料为准；不混入 A7/A8 配置。
- **尺寸资料**：[A6 尺寸表](leopard-a6-dimensions.md)集中记录来源、型号口径和量化结果。部分公开依据描述 A6M，不能据此声称普通 A6 的全部局部尺寸均已实测；照片比例估算须明确标记。
- **美术精度与物理**：0.02 米体素用于实际细节作者化；主要车体沿用单一简化圆角碰撞框，边界按 0.1 米量化，炮管及细小附件不单独增加碰撞。
- **玩法取舍**：保留现有驾驶与战斗参数。炮塔仍属于 body、随整车瞄准，本次不增加独立转塔、炮管俯仰或悬挂模拟。
- **弹丸目标**：参考与 L55 相容的 DM53/DM63 系列 APFSDS 脱壳后飞行体，尽量采用真实比例和简化尾翼；不把完整弹壳随弹丸发射。视觉与既有 0.4 米扫掠碰撞分别维护，不由真实弹药性能改写游戏参数。
- **状态（2026-10-29）**：美术返工进行中。真实引擎视觉样板（leopard-player-rework 工单 01）已经用户确认采纳，作为后续细化依据；整车最终美术验收待返工完成后另行复核。详见[视觉样板确认](testing/player-a6-final-acceptance.md#视觉样板确认leopard-player-rework-工单-012026-10-29)；旧 01–06 记录是被拒绝外观的技术历史。

模块导航：共享体素尺度和 `WheelSpec` 位于 `src/tank/model/mod.rs`；生成器 `scripts/generate_player.rs` 复用车型契约，交付资产统一经 `scripts/publish_player.py`（生成→细分→发布）产出。驾驶、履带、炮管挂载归 `src/tank/`，对局生成归 `src/gameplay/session.rs`。目录整理验收见 [任务 10](testing/architecture-step10-20261023.md)。

默认玩家为真实尺度豹 2A6，每侧七负重轮与两个端轮（工单 03 交付），
装甲分区与车顶附件细节已交付（工单 04）；真实比例弹丸已由工单 05 交付。
保持既有驾驶与整车瞄准；炮塔仍属 body，不支持独立转塔或俯仰。

## 尺寸和坐标

完整的资料边界、型号、端点和量化结果见 [A6 尺寸表](leopard-a6-dimensions.md)。
共享契约为 `src/tank/model/player.rs`：运行时与轮位使用 0.1 米参考格，
`VISUAL_HULL_X` / `TURRET_X` / `TURRET_TOP` 明确使用 0.02 米资产格；不混用两种单位。
交付三包都使用 0.02 米 meta；完整契约共用的参考画布在 2026-10-29 扩为 144×38×37（资产画布 720×190×185），
扩高全部位于车体屋顶以上；运行时轴心 `CANVAS_PIVOT=(72,19,13.5)` 保持旧画布中心
高度，作者源 `player_a6.py` 的 `Z0=25` 把几何整体上移 25 资产格，抵消 VOX 插件
以画布中心为原点的偏移。三包零偏移组合，不按包含炮管的 AABB 重新居中，
不使用运行时整体缩放。

- 非炮管视觉长 7.66 米、全宽 3.76 米（分段裙板外沿），炮塔主体顶高 2.64 米；
  舱盖、观瞄、车顶机枪与天线最高体素离地 3.02 米（视觉样板解除 2.70 米压缩）。
- 炮管从参考 X=95 到 143.6，外露 4.86 米；炮轴离地 2.08 米。
- 炮口相对 body 根前方 7.16 米；车尾至炮口全长 10.98 米，比 10.97 米参考长一细格以内。
- 主要几何向外取 0.1 米后的单一圆角框为 7.8×2.7×3.8 米（长×高×宽），圆角仍 0.2 米。
  视觉边界独立，附件不用于扩高碰撞，炮管没有碰撞。框内空隙仍参与命中。
- 弹丸视觉为 0.72×0.10×0.10 米细长尾翼飞行体；0.4 米扫掠碰撞和战斗参数保持。
- 相机仍为后退 16 米、抬高 9 米、抬头角 8°；画廊与详情按实际旋转包络自动适配。

## 三包与替换规则

| 资源路径（相对 assets） | 节点 | 内容 |
|---|---|---|
| tank/bodies/player/anvil/body.vox | body | 车身、炮塔、炮盾、裙板、舱盖、格栅、观瞄、天线、车顶机枪 |
| tank/barrels/player/lance/barrel.vox | barrel | 炮管根部、管身、抽烟器、炮口 |
| tank/tracks/player/cleat/track.vox | track_l_0..2 / track_r_0..2，wheel_l_0..8 / wheel_r_0..8 | 六个履带相位、十八个独立轮 |

三部件统一按 `tank/<部件>/<车型>/<变体>/` 分包，变体目录名即型号 ID（玩家车体 `anvil`、炮管 `lance`、履带 `cleat`），包内主模型固定为 `body.vox` / `barrel.vox` / `track.vox`。子弹是 `lance` 炮管的附属资源，与其同目录的 `bullet.vox`，运行时与发布管线均使用该路径。换装只需替换变体目录，详见 `docs/adr/0001-tank-asset-packages.md`。

三包共享调色板；车身、炮管和履带相位以全局画布零偏移挂载。轮子粗源使用8×4×8（负重轮）或5×4×5（端轮）参考格局部画布，交付时细分为 0.02 米资产格，按 `WHEELS` 的轴心安装。替换资源必须保持该契约；需要改变炮管长度或轴线时，先修改共享尺寸定义、生成器和相关测试，不通过运行时缩放掩盖不兼容。履带齿距 15 资产格、每行驶 5 资产格推进一相位，梯形闭环 840 资产格（16.8 米）。轮子按对应侧累计里程除以滚动半径绕游戏Z轴连续旋转，停车保留角度；每个节点必须完成加载和实例化，缺失节点会报错。

## 生成与验证

```powershell
python scripts/publish_player.py           # 命名画布/轮粗源→细分→0.02米主体作者化→配对发布
python scripts/publish_player.py --check   # 只校验管线产物与交付资产逐字节一致，不写文件
rustc --edition 2024 --test scripts/generate_player.rs -o target/test_generate_player.exe
./target/test_generate_player.exe
python -m unittest discover -s scripts -p test_player.py
python -m unittest discover -s scripts -p test_tracks.py
cargo check
cargo test
```

统一入口不读取交付资产作为造型输入。Rust 生成器提供命名画布、材质及独立轮粗源，
转换器细分轮子并处理 meta；`scripts/player_a6.py` 直接在 0.02 米格上生成车体、炮管和
六相位履带，复用已有分块规划和场景类型。车体/炮管不再依赖旧粗几何，尾舱仍有真实细格凹槽。
子弹由发布脚本直接以细网格作者化，不再使用旧粗弹丸快照。直接运行 Rust 生成器仅得到临时作者化输入，
不是完整交付模型；已配置细网格 meta 的交付位置仍被直写守卫拒绝。

每个部件在临时目录完整生成、回读验证后才调用既有 VOX/meta 配对发布；整套四部件不保证事务。
`--check` 重建并逐字节比较四配对，不写 assets；失败保留临时诊断。
`test_player_scale.py` 用交付资产验证真实尺寸、炮轴和主体屋顶，`test_tracks.py` 按资产格
验证 840 格梯形闭环三相位；真实加载测试验证装配、炮口、预览取景和实例清理。
最终运行 scene、drive、combat、wheels、gallery、detail 离屏并读取关键帧。
本票证据和限制见 [真实尺寸基础整车验收](testing/player-a6-assembly.md)。

## 尾翼弹丸（工单 05）

飞行体参考 DM53/DM63 系列的细长脱壳外观；[Rheinmetall 系统资料](https://www.rheinmetall.com/Rheinmetall%20Group/brochure-download/Weapon-Ammmunition/B195e0423-Rheinmetall-120mm-system-house.pdf)确认 DM63A1 兼容 L55，但未给出飞行体几何尺寸。[公开报道](https://militarnyi.com/en/news/ukrainian-leopard-tanks-received-modern-dm53-armor-piercing-rounds/)称 DM53A1 穿杆长约 0.685 米、直径约 0.026 米，不能把它视作完整飞行体实测。按报道的穿杆长度加约 0.035 米尾端估算全长约 0.72 米，尾翼包络按杆径约四倍估算为 0.10 米；该比例是低精度造型假设。杆径约 0.026 米，为表达单格尖端，量化为 0.04 米（误差 0.014 米）。三者分别量化为 36、5、2 格；尾翼尺寸和全长是造型估算，并非厂家数据。单格尖端无法表达亚格锥面。通用 APFSDS 的脱壳及尾翼外形参考 [示意图](https://commons.wikimedia.org/wiki/File:APFSDS_Diagram.png)，该图并非 DM53/DM63 实物或尺寸依据。

弹丸直接生成并回读为 0.02 米资产；没有弹壳或弹托。视觉中心相对既有扫掠中心向前 0.16 米，使 0.72 米弹体尾端与炮口端面相接。扫掠盒、弹速、射速、射程及伤害保持原值。配对发布和 `--check` 沿用统一入口，旧粗快照不再参与弹丸生成。

2026-10-29 在 NVIDIA GeForce RTX 4060 / Vulkan 的 combat 离屏中验证生成、飞行、命中、爆炸及清理，读取出生近景和正常镜头首发帧；近景可见尾翼和收窄尖端，正常镜头下弹丸几乎不可辨。射程及场景实例清理由逻辑和真实资源测试覆盖。没有进行可见窗口测试；尺寸为公开资料与造型估算，不是工程测量。

### 轮廓优化验收

生成器4项、玩家资源3项、履带资源1项测试通过；Rust测试41项通过，`cargo check`通过。Windows RTX 4060 / Vulkan上的scene、drive、combat报告通过，已读取关键帧；drive直行约6米、转弯正常，combat仍使用抬高靶车。

本机证据为 `.scratch/offscreen/player-refined-{scene,drive,combat}-01/` 和 `.scratch/model-refined-inspection/`。后者包含side/front/rear同视点截图、collision黄色外包围框图及comparison.md前后对比。黄色框不描绘0.2米圆角，仅用于确认整体尺寸和中心；真实圆角范围由旋转碰撞体测试校验。拍摄代码仅在忽略目录的检查副本内，正式游戏镜头未改变。
