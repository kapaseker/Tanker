# Tanker 美术风格基线

- 基线版本：v1（2026-10-30）
- 风格名称：**精细体素半写实风格**
- 决策状态：用户已确认风格方向，并授权归档与规范接入。
- 实现状态：田园近景细化版真实引擎样板已实现并通过硬件离屏验证；[实际画面与限制](testing/pastoral-preview-2026-10-31/README.md)待用户美术确认，尚未完成整体风格验收。

> Tanker 采用精细体素半写实风格：真实比例、可信结构、清晰块面、层次化细节、克制配色与自然光照。所有地图与资产围绕这套视觉语言展开，题材保持开放。

以真实世界的比例、结构和材质为基础，用清晰可见的体素块面进行艺术化概括，再通过自然光照、柔和阴影和空气透视，形成厚重、细腻、有空间感的画面。“半写实”表达可信的形体与材质，“体素”是明确可辨的造型语言；风格名称是对选定参考图的描述性归纳。

## 适用范围与边界

本基线适用于坦克、地形、建筑、植被、材质、灯光与特效，也适用于后续新增题材的资产和地图。

**参考图用于约束形体、体素层次、材质、色彩关系和光照气质。图中出现的地貌、植被、建筑、天气、季节与构图仅为表现示例，不构成地图设计范围或内容要求。** 不按参考图列出地图清单，不要求复现其中的对象与场景。

本基线不规定统一体素尺寸、具体渲染参数或新增玩法；作者化精度与性能预算需要在实际引擎样板中确定。坦克的现实型号、尺寸与机械结构以[车型目录](tank-catalog.md)和对应模型资料为准，不从风格参考图推导尺寸。UI 继续遵循根目录 [design.md](../design.md)，不从参考图直接采色替换 UI token。

## 视觉规则

| 维度 | 应达到的视觉特征 | 需要避免的偏离 |
| --- | --- | --- |
| 形体与比例 | 整体轮廓清晰，体积与重量可信；机械对象保留可理解的装配结构 | 夸张的大头比例、轻飘的薄片结构、细节掩盖主体 |
| 体素表达 | 块状几何和阶梯边缘可见；大块面建立主体，中小体素表达结构与细节 | 全部对象采用相同颗粒大小、均匀碎块堆砌、把体素仅做成表面纹理 |
| 细节组织 | 先读懂整体，再看到零件与表面变化；细节依附结构，疏密有序 | 无意义的小块与高频噪点覆盖所有表面，正常游戏镜头下轮廓破碎 |
| 材质 | 以色块、粗糙度与几何层次区分材质，适度呈现表面变化与使用痕迹 | 普遍光滑的塑料感、所有材质共用相同高光、为做旧而堆积污渍 |
| 色彩 | 配色协调、饱和度克制，局部颜色形成重点；具体色相随地图自由变化 | 把某张图的色相定成所有地图的固定色盘、全画面等强度争夺注意力 |
| 光照与空间 | 自然光感、柔和阴影、接触处明暗和远近空气透视共同建立空间，块面仍清楚 | 高光与后期效果吞没体素形体、暗部丢失主体与目标轮廓 |
| 整体气质 | 精致、厚重，有自然环境感；真实结构与体素艺术化概括协调 | 机械照搬照片细节而失去块面概括，或任意简化到失去可信结构 |

表中的视觉目标不绑定具体 shader 或渲染算法。特效沿用相同块面与色彩层次，服务动作和命中信息，不遮蔽持续观察所需的信息。

## 落地与验收

1. 修改美术前读取本基线和相应资产契约，说明本次涉及哪些视觉维度；地图题材自由选择。
2. 先制作一个小型真实引擎样板，覆盖主体、环境块面、材质与光照的关系。样板仅验证视觉语言，不因示例资产生成地图内容承诺。
3. 按工程离屏入口输出正常游戏镜头及必要细节图，检查退出码、报告和实际关键帧。检查整体轮廓、体素层次、材质差异、配色关系、空间深度，以及主体和目标的辨识度；HUD 在实际背景上按 UI 规范检查。
4. 分别记录技术验证结果与美术对照结论，请用户确认真实引擎样板。自动检查、资源加载成功或图片非纯色都不能替代美术认可。
5. 样板确认后再扩展资产与地图。最终验收把基线版本、实现提交、参考图、关键截图、差异、用户确认与平台限制写入长期记录，避免只引用本地临时产物。

长期状态与证据入口：[基线落地验收记录](testing/art-direction-baseline.md)。本地后续工单位于 `.scratch/art-direction-baseline/`，不随 Git 共享；缺少本地工单不影响本文件作为风格依据。已有模型的历史验收继续保留，不能直接当作本基线的整体验收。
