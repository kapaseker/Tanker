## 检查和结果

- `cargo check` 通过。
- `cargo test -- --test-threads=1` 最终113项通过（104单元、5元数据、4分块集成）。
- 独立 Rust 玩家生成器4项通过，Python全套44项通过；发布独立入口2项通过。
- 统一发布重建后四个配对逐字节一致；检查模式前后全部坦克 VOX/meta 的哈希和
  写入时间相同。漂移诊断测试覆盖 VOX/meta 不一致；原有转换器发布回滚测试仍通过。
- scene、wheels 新旧离屏退出0，报告全部通过；真实加载的尺寸、原点、实例、
  落地、前进/倒车/转向/停车断言保持。战斗行为由真实资产开火与清理集成测试覆盖。
- 已读取新旧正、侧、后、前侧上方、正常游戏镜头及 `grille.png` 近景，
  新格栅比旧粗条更密，槽内深色与下凹一格可辨，整车轮廓和5+2轮组保持；
  读取新 wheels 转向帧90，轮组围绕轮轴转动，未见明显穿插或分块裂缝。

首次细节断言在旧资产失败、重建后通过；诊断保留在工具输出。
首次 Python 全套受系统临时目录权限和子进程 GBK 默认编码影响；最终运行设置
`PYTHONUTF8=1`，`TMP`/`TEMP` 指向仓库 `target/test-tmp`，无需改敌方代码。
首次 Cargo 运行遇到正在使用的 exe；随后全套有一次履带缺失节点10秒超时，
新旧资产单独重跑均通过，最终串行全套通过。失败日志均保留，不调整超时或断言。
