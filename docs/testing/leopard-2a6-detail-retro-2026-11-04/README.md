# 豹 2A6 详情页外观迭代复盘

日期 2026-11-04。适用于新坦克的建模、发布和详情页画面验收。豹 2A6 使用 [astraH 作者源与运行资产契约](../../player-model.md)。本次用 [07 右后概念图](../../references/leopard-2a6-style-v2-2026-10-30/07-rear-right.png) 对照光照、地面、取景和细节层次。概念图之间的部件布局存在冲突，几何按[车型资料](../../tank-catalog.md)核对。

## 这次调整如何收敛

| 阶段 | 观察与调整 |
| --- | --- |
| 接地与交互 | 将二维网格换成混凝土地面，详情镜头改为绕车环行。切换后垂直拖拽曾反向。修复后，离屏预设直接检查同一近侧标记在相机坐标里的上下位移，同时核对车体保持水平。 |
| 光照与材质 | 旧预览继承对局的强环境光，轮毂和格栅的明暗被填平。展台改用独立环境光、暖主光与冷补光，随后分开车漆、裸钢和观瞄件的材质参数。先用同一模型确认布光能揭示已有细节，再判断哪些面确实需要改几何。 |
| 局部几何 | 侧裙在原包络内挖出凹面，增加折边和紧固件。负重轮加深凹盘，履带拉开钢板与胶垫的高低差。整车包络、轮轴位置、履带接地高度和碰撞尺寸沿用原契约。运行时只有车体与履带包发生变化。 |
| 发布校验 | 旧发布脚本把体素总数写死，合法几何改动被拒绝。现从作者源计算总数，并继续逐组比对体素位置和颜色，核对材质块以及履带相位接地。 |

### 同机位画面对照

[旧几何](rear-right-baseline.png) · [新几何](rear-right-candidate.png)

两帧使用同一版灯光、材质配置和详情 UI，固定右后角度、16° 镜头仰角和 1.20 倍缩放。这个对照用于观察几何差异，灯光变化应单独做同模型对照。新版最容易读出侧裙框边和紧固件，轮毂凹盘其次，履带胶垫在整车帧里仍比较细微。与概念图相比，多盏暖光近似的阴影仍有分层，近景尺寸标签可能碰到左侧参数区。

### 已验证的范围

- 作者源结构回读、运行包重生成对比和发布脚本单元测试通过。
- `cargo check --locked` 通过。详情、炮塔动作和轮组预设在 Windows、RTX 4060、Vulkan 上退出码均为 0，报告均为通过。离屏运行使用项目上一版 Bevy 特性配置的本地编译缓存。
- 本记录归档的是已验证的迭代结果。完整美术验收、可见窗口输入和其他平台待验证。

## 新车型按这个顺序验收

1. **先定依据。** 分别记录车型尺寸和结构来源、风格参考及对应视角。为车体包络、轮轴、炮塔与炮管枢轴、炮口和履带接地写下可测的目标。动手前选定一个常用视角和一个最能暴露目标细节的近景。
2. **先拍基线，再分层改。** 用项目真实引擎拍默认视角和固定近景，记录镜头、缩放、分辨率和灯光。用同一模型先排查环境光、材质和取景。改几何时锁定灯光和镜头，只做一组典型部件，直到目标细节在正常浏览尺寸下可辨。近景用于解释差异，默认帧用于判断玩家能看到什么。
3. **先在隔离资产目录验证，再发布。** 从作者源生成临时运行包。逐组对照默认姿态的体素与材质，检查枢轴、轮组尺寸和履带各相位接地。任何数值变化应能对应到明确的设计决定。通过后再发布，并重生成比对实际运行包。发布校验从源数据推导预期值，车型约束单独检查。
4. **跑对应预设，读报告也读图。** 按[离屏预设选择](../offscreen-presets.md)，展示与环绕用 `detail`，轮组及履带用 `wheels`，涉及炮塔、炮管或共享运行资产时按受影响路径补 `articulation` 等预设。检查退出码、GPU 后端、报告和关键帧。环绕与缩放看接地、拖拽的屏幕方向、尺寸标签可读性，以及回到画廊时的状态。
5. **归档一对可比较的图。** 在车型记录里保留参考图、同机位前后帧、实际资产版本、验证结果和已知差距。技术验证与用户美术确认分别记录。

## 后续可加强的检查

1. **标签避让。** 若调整详情构图，优先把尺寸标签与参数面板的重叠做成离屏断言，至少覆盖默认、右后近景和窄视口。当前方向断言已覆盖垂直拖拽，这项检查覆盖的是另一个问题。
2. **发布门槛。** 把作者源回读和运行包重生成比对作为每次共享资产发布的检查项。优先复用各车型的生成与验证脚本，并记录运行命令与产物版本。
