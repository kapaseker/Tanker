# VOX 模型单位配置与坦克五倍细分规格

Status: ready-for-agent
Type: specification
日期：2026-10-28
范围：规划完成；尚未实施。

## Problem Statement

当前所有 VOX 由同一个全局 0.1 米加载参数控制，不能通过各资产的配置表达单位长度。用户希望先接入单位配置并保持当前游戏画面不变，再把全部现有坦克资产改为 0.02 米/格。

用户已补充：本次只分更多格子，不重塑、雕刻、改色或新增美术细节。细分后仍须与原模型具有同样的可见外形。

## Solution

先为现有 VOX 加入资产单位配置，让 Bevy 在生成网格与场景变换前读取配置。现有资产先全部明确配置为 0.1 米，完成兼容验收。

再将每个坦克原体素替换为同色的 5×5×5 个体素，并把相应资产配置改为 0.02 米。原模型的物理尺寸、原点、节点语义、颜色、运动及装配关系保持不变。超出 VOX 单模型坐标范围的几何拆成同一文件中的多个子模型。

单位配置必须真正参与加载器的网格烘焙和场景坐标换算；不以固定 0.1 米加载后缩放视觉根节点代替这一要求。

## User Stories

1. 作为开发者，我可以在模型旁的配置中查看和设置一格对应的米数。
2. 作为玩家，配置接入后看到的旧模型与接入前一致。
3. 作为开发者，我可以在同一场景混用 0.1 米和 0.02 米的模型。
4. 作为开发者，加载带命名节点的场景时，所有子模型共享所属文件的单位配置。
5. 作为开发者，我得到全部现有坦克资产的 2 厘米网格版本，供后续修改。
6. 作为玩家，坦克、炮管、子弹、轮组和履带不会因细分缩小、移位或变形。
7. 作为玩家，车辆碰撞、炮口发射位置、车轮转动与履带滚动保持原有行为。
8. 作为开发者，我可以确定性地重建细分资产，并验证每个原体素的颜色和占用体积都被保留。
9. 作为开发者，我能识别错误配置、重复细分和坐标溢出，避免写出损坏资产。
10. 作为开发者，我能在实际对局、画廊和详情中验证同一资产，而不依赖可见游戏窗口。

## Implementation Decisions

- 阶段 A：配置接入，所有现有模型保持 0.1 米，VOX 文件内容不变。
- 阶段 B：仅现有坦克目录内七个 VOX 文件改为 0.02 米；爆炸和混凝土墩仍为 0.1 米。地形不是 VOX，不改动。
- 七个文件覆盖玩家和敌方的车身、炮管、履带包，以及玩家已有子弹。履带包内轮子、每侧三个履带相位一并转换。当前敌方子弹只是装备字段中的占位路径，没有对应资源或开火能力，本次不新增。
- 优先使用 Bevy 原生资产元数据作为模型旁的配置，将单位传给现有 VOX 加载器；先以真实加载器验证，不能把插件注释当成已经复现的故障。
- 取消运行时和测试中的全局加载参数覆盖。原有材质、网格偏移、颜色空间、CPU 数据保留等设置必须逐项保留，不得因改单位配置隐式改变。
- 如果原生元数据不能可靠覆盖命名子资产、场景平移或动画依赖，先留下失败证据和修订方案，再处理替代加载入口；不得悄悄退回运行时缩放或升级依赖。
- 一个文件一个单位；不支持同一文件中不同子模型使用不同单位。本次不增加通用模型编辑器、热更新或其他配置字段。
- 严格进行有色体积细分：原格坐标 p 的每个子格坐标为 5p+d，d 每轴取 0～4，颜色索引与调色板不变。对应长度由 5×0.02=0.1 保证。
- 分块时保留语义父节点；分块是该节点的子树，不改变炮管、轮轴和履带相位的名称、坐标系和生命周期。
- 分块局部坐标只能为 0～255；场景变换采用整数格平移。必须处理整体画布与子块尺寸的奇偶性，必要时补空白画布，不能把半格偏移四舍五入。
- 当前尺寸/轮位契约仍可保留在原作者化 0.1 米参考网格中，常量应改名或说明其职责，避免与资产实际 0.02 米网格混淆。运行时几何及物理统一比较米制值，不将参考格数当作资产 SIZE。
- 不把所有契约数值机械乘五，也不把全局旧常量直接改成 0.02。碰撞体、轮半径、炮口和装配点的米制值保留。
- 履带保留每侧三个相位、每相位移动 0.1 米、齿距 0.3 米；细分后分别对应 5 和 15 个资产格。车轮角度仍为里程除以米制半径。
- 子弹保留当前 1.2×0.4×0.4 米视觉尺寸及独立 0.4 米扫掠碰撞参数，不根据过时文档把视觉改成正方体。
- 不删除内部体素、不挖空、不平滑斜面、不改轮廓或材质。允许分块导致网格拓扑不同，但彩色实体占用的米制体积必须相同。

## Testing Decisions

- 主测试入口使用真实资产加载器与实际场景装配，比较变换后的几何、原点、命名子资产与就绪/清理行为。
- 用小型无 GPU 资产覆盖不同单位、非零场景平移、奇偶画布、超过单模型范围、命名子资产加载和配置错误。
- 细分转换测试将输出场景还原到共同整数坐标，再核对每个子格能唯一映射到原格、颜色一致、无漏格/重叠、数量精确为原来 125 倍。
- 源占用检查与米制顶点/包围盒检查同时保留；只有尺寸相同不足以证明细分正确。
- 配置阶段旧 VOX SHA-256 完全相同；细分阶段七个坦克 VOX 改变，非坦克资产 SHA-256 保持。
- 视觉兼容使用同一环境、相机、灯光、随机种子和模拟帧比较。旧资产接入配置阶段要求无可见差异；细分阶段允许网格重分块的微小浮点栅格化差异，不能接受轮廓、色块、接缝或运动变化。
- 不用放宽断言、删除清理测试或只检查图片非纯色来通过验收。受分块影响的固定网格数量断言改为语义完整性及无残留断言。
- Rust 修改后必须通过 cargo check；相关测试和离屏验证按计划执行。没有目标硬件测试时，不能声明性能通过。

## Out of Scope

- 模型美术精修、更多斜面、圆管、轮毂、装甲细节、换色或改变体积。
- 新建敌方子弹、敌方开火、车型或装备。
- 修改地形、混凝土墩、爆炸动画的尺寸或精度。
- LOD、引擎/插件升级、依赖源码修改、逐体素碰撞、UI 布局或交互改造。
- 本轮只制定方案，不实施转换、启动游戏、提交或推送。

## Success Criteria

- 配置先于 VOX 网格烘焙生效；0.1/0.02 同场混用的真实加载测试通过。
- 阶段 A：九个旧 VOX 字节不变，尺寸、颜色、场景、动画与交互表现保持基准。
- 阶段 B：七个坦克 VOX 的配置为 0.02 米，43 个源模型的全部有色体素精确细分；不要求分块后仍为 43 个模型。
- 非坦克资产内容、单位与实际尺寸不变；物理、炮口、轮轴和履带相位保持米制基准。
- 生成流程能重现细分产物，不会用旧粗模型覆盖细模型并遗留 0.02 配置。
- 测试、离屏图片/报告、资源与性能对比明确记录；未通过项如实保留。

## Further Notes

本规格遵循用户本轮“仅细分”的修正，替代此前讨论中的美术精修目标。技术路线中的原生元数据是优先方案，需任务 01 的真实加载验证后定案。任务状态表示规划已可供执行，不表示实现完成或已经自动开始执行。
