## 3. 配置接入方案

### 3.1 优先采用平台现有资产元数据

每份文件旁放置 `body.vox.meta` 一类原生 RON 元数据，loader settings 中明确 `voxel_size: 0.1` 或 `0.02`。示例仅表示字段，不是可直接复制的完整 meta 文件。完整格式、加载器类型名和其余设置由锁定版本生成/验证后保存。

加载顺序：AssetServer 查询模型旁元数据 → 反序列化加载设置 → VOX 加载器按 voxel_size 生成网格并换算 nTRN 平移 → WorldAsset / 命名子资产 → 对局或预览装配。

现有 `src/app/mod.rs` 注册了 `global_settings: Some(...)`，插件加载实现使用全局值优先，会覆盖 meta 的单位；生产和测试都必须改为允许各文件配置。`.meta` 必须随资产分发，AssetPlugin 的 meta_check 不得禁用这些文件。

插件源码仍有“load_with_settings 存在问题”的注释；本方案不依赖该函数。任务 01 必须实际验证原生 meta、整场景和 `#命名节点` 的传递，而不是仅依赖注释判定成功或失败。

保持原有偏移、颜色空间、粗糙度、发光强度、网格/体素数据保留设置。配置缺失不得默默采用插件默认的 1 米：资产完整性检查覆盖全部受管理 VOX，加载/就绪入口报告缺失或非法配置；实施时优先用最小的现有资产检查接缝实现，不增加通用配置框架。输入要求单位为有限正数；损坏配置要出现明确失败和路径，不能以加载超时替代原因。

若原生方案失败，01 记录最小复现及可替代入口的影响，先修订方案再实施；不以固定尺度烘焙后 Transform 缩放当作配置生效的验收。

### 3.2 保留参考坐标与资产坐标的区别

现有 `src/tank/model/{player,enemy}.rs` 是纯标准库作者化契约，Rust 生成器直接引用，Python 生成器通过字面量读取。保留这些契约的原参考格数及其 0.1 米参考单位可以避免无必要的整库数值迁移。

- 参考格：旧尺寸/轮位契约使用，换算到米时仍乘 0.1。
- 资产格：真正写进新 VOX 的格子，配置为 0.02。
- 世界/物理：米。车轮轴心、滚动半径、炮口、碰撞框与里程均在米制下验证。

旧 `VOXEL_SIZE` 在移除全局加载用途后，应改为职责明确的参考网格常量，并更新全部调用与中文注释。资产加载单位来自元数据，不能继续复用这个旧常量。未来原生细网格美术作者化可另改生成流程，不在本次扩展契约。

配置值与转换因子不能成为无检查的两套真值：生成器输出新单位配置，转换器验证 source_unit / target_unit = 5，资产测试核对 meta 和生成参数一致。

## 4. 精确细分与分块算法

1. 读取源 VOX，验证版本、各 chunk 长度、模型引用、节点 ID、颜色索引与坐标范围。只支持本次七个真实文件所需的格式；遇到未支持动画/旋转等内容明确报错，不忽略未知语义。爆炸不走此转换器。
2. 对每个源体素 `(x,y,z,c)`，产生 `(5x+dx,5y+dy,5z+dz,c)`，每个 d 为 0～4。调色板和材料属性逐字节保留。
3. 单个模型未超过每轴 256 格时直接输出；超出时按空间分块，将坐标移到各块的 0～255 内。只创建有体素的块。
4. 以加载器的模型居中约定计算块平移：VOX 格坐标下 `t = origin + (chunk_size - full_size)/2`。源 nTRN 的格平移乘五；原节点旋转及语义父关系保留。公式必须通过真实加载器交叉验证坐标映射，不能只验证自写解析器。
5. `_t` 是整数格，故各轴 chunk_size 与 full_size 必须同奇偶；可选 255/256 格块并给末块补必要空白。禁止舍入半格误差。重点覆盖 675 格奇数画布和 570 格偶数画布。
6. 保留原具名 transform；把原 shape 的几何替换为块 transform/shape 子树。命名子资产仍返回整部件，不能只取一个分块。相位父节点统一控制全部子块，轮子仍绕原轴心转。
7. 使用流式写出/按块分配，避免为 855 万个体素建立 Python 三元组字典。每个 XYZICount 及 chunk 长度先计算/核对；重复体素或丢失体素直接失败。
8. 全部输出先写入新 staging 目录，验证成功后再替换目标 VOX 与配置。失败保留原资产；重复执行不能把已经 0.02 的模型再次细分，不覆盖已有证据目录。
9. 把新场景还原到同一整数格坐标，核对每个旧格恰有 125 个同色子格。再由真实加载器比较米制变换、包围盒和原点。

分块会改变网格与模型数量，不应改变有色体积。不能用删内部体素、变成空壳或自动重塑来压资源量，因为本次要求严格细分。

## 6. 逐阶段验收

### A：配置兼容

旧 VOX 哈希完全不变。固定场景/画廊/详情各留基准帧；对比模型尺寸、材质设置、炮口和轮轴。小样同场 10 格×0.1 米与 50 格×0.02 米都为 1 米，同时包含非零节点平移、命名子资产和动画场景。所有配置错误可诊断，无默认 1 米的静默回退。

### B：玩家样板

先细分 body/barrel，仍与旧履带/子弹混用；随后细分履带及轮子。玩家非炮管碰撞保持 7.5×2.6×3.6 米，完整可见长保持 10.5 米。轮子半径/轴心与原模型相同。三相位连续移动、倒车、原地转向、停车均保持。检查分块边界无裂缝、色差和可见内部面异常。

### C：全部坦克资产

敌方非炮管尺寸保持 6.6×2.6×3.4 米，完整可见长 9 米；子弹仍为 1.2×0.4×0.4 米视觉、0.4 米扫掠。七个单位配置都是 0.02，体素总数精确为 8,557,250。混凝土墩、爆炸与地形文件哈希不变。

按正常游戏距离与轮组近景各比较固定帧；不靠调整相机、光照或曝光掩盖差异。若只出现少量浮点栅格化误差，记录位置与原因；任何外轮廓、颜色分区或动画差异都需修复。

## 8. 风险与恢复

| 风险 | 处理 |
|---|---|
| meta 或命名子资产设置不生效 | 01 小样前置，真网格尺寸证明；失败先修方案 |
| 取消全局设置后遗漏资产变成 1 米/格 | 九个配置完整性检查、故意缺失/损坏配置测试、检查所有测试组装 |
| 分块半格偏移/原点变化 | 奇偶画布、正负平移小样；真实装配与米制顶点检查 |
| 分块导致履带只切换一块或只测一个网格 | 语义父节点控制可见性，变换后子树合并测量 |
| 数据精确增长 125 倍 | 接受该任务固有成本；流式生成，保留全部体素，实测加载/内存/帧耗时 |
| 旧生成器覆盖新资产 | 统一发布入口写出 VOX+meta，生成测试比较最终细分产物 |
| 当前工作区存在他人修改 | 基准记录改动与哈希，不重置/清理，不把它们纳入本任务提交 |
| 转换失败/半发布 | staging 全量验证后发布，保留细分前 VOX+meta；配对恢复资产和配置，不单独恢复一方 |

配置阶段与各车型迁移分成可回退提交；未来只有用户要求才提交/推送。实施前的 Git 状态、原文件哈希与证据目录要可追溯。
