# ADR-0002：按使用场景与共用能力组织单 crate

- 状态：已采纳
- 日期：2026-10-23

## 背景

原根目录模块混合了应用组装、玩家控制、共用能力与验证工具。整理保持单个 Cargo package，保留依赖、资产、玩法、视觉、调度顺序和命令行契约。

## 决策

- `app` 组装所有功能，`main` 负责参数解析和退出码；页面和对局可用应用状态与过渡接口，不调用启动函数。
- `pages` 与 `gameplay` 是不同使用场景。画廊只组装视觉，不接入玩家控制、敌人生成、武器或驾驶物理。
- `tank`、`terrain`、`ui` 生产代码不依赖页面、对局、应用状态或验证入口。驾驶消费 `DrivingInput`；`tank::model` 的尺寸和轮位为纯标准库契约，生成器直接复用。
- `gameplay::session` 拥有对局标记并聚合业务就绪和清理，地形提供自身清理入口；过渡继续检查真实 GPU/纹理就绪。
- 固定随机配置经启动入口注入 `SpawnConfig`，业务不读验证参数；`EnemyDestroyed` 归敌人领域，由战斗生产、爆炸消费。
- 子模块默认私有，接口按实际调用范围使用 `pub(super)` 或 `pub(crate)`；不保留旧根模块兼容入口或全项目 prelude。

## 最终检查与取舍

旧根模块入口已在前序任务移除。现存四处重导出是职责接口：validation 的 Options、configure/run，画廊 Previews，以及仅测试构建的 terrain::spawn_arena；不是迁移兼容层。

`tank::track` 和 `terrain::collider` 的测试仍引用玩家身份/控制，以验证真实履带与键盘驾驶、翻坎的跨模块行为。这些 `cfg(test)` 引用不是生产反向依赖；保留原断言，不为文本零命中复制业务实现或移动测试。

不增加 crate 或依赖约束工具，单 crate 的逻辑边界由源码评审维护。旧路径在计划和历史问题记录中保留历史语义，通过当前导航定位实现。完整回归及已知失败见 [任务 10 验收](../testing/architecture-step10-20261023.md)。
