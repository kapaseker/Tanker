# ADR-0005：VOX 单位按资产配置，参考格与资产格双格制

- 状态：已采纳
- 日期：2026-10-29

## 背景

所有 VOX 原由 `VoxScenePlugin` 的全局 `global_settings`（0.1 米/格）统一控制，单位无法按资产表达。
用户要求坦克资产改为 0.02 米/格（每原体素替换为同色 5×5×5 子格），同时保持世界尺寸、原点、
装配与动画行为完全不变。bevy_vox_scene 0.23 的加载器支持 Bevy 原生资产元数据
（`.vox.meta` RON，`settings.voxel_size`）在网格烘焙前生效。

## 决策

1. **单位一律来自每文件的 `.vox.meta`**：`global_settings` 恒为 `None`（生产与测试组装一致），
   加载器按各文件 `voxel_size` 烘焙网格并换算 nTRN 平移；不以"固定尺度烘焙后缩放 Transform"代替。
2. **启动守卫**：`src/app/vox_meta.rs` 在任何加载开始前遍历资产根 `assets/` 下全部 `.vox`，
   要求配对 meta 可解析、loader 为真实 `VoxSceneLoader`、`voxel_size` 为有限正数，违规 panic
   并带完整路径。插件对缺失 meta 会静默回退 1 米/格、对非正/非有限值不校验，守卫补上这两类防线。
3. **一个文件一个单位**：同一文件内不同子模型不支持不同单位；本次不增加通用模型编辑器或热更新。
4. **双格制**：
   - 参考格（0.1 米，`REFERENCE_VOXEL_SIZE`，`src/tank/model/`）：作者化尺寸、轮位、炮口契约，
     数值不随细分改变，换算米制时乘 0.1；
   - 资产格（交付 VOX 实际网格，已细分坦克资产为 0.02 米）：只存在于资产文件与 meta；
   - 运行时几何与物理统一比较米制值，不把参考格数当资产 SIZE，也不把契约数值机械乘五。
5. **细分只分格、不做美术**：转换器 `scripts/subdivide_vox.py` 强制 source_unit/target_unit = 5，
   拒绝重复细分；VOX 与 meta 配对原子发布、失败配对回滚；生成器只产出 0.1 粗样，
   交付必须经统一发布入口（`publish_player.py` / `generate_enemy.py --check`）。

## 后果

- 阶段 A（配置接入）九个旧 VOX 字节不变、画面零差异；阶段 B 七个坦克文件体素精确 ×125
  （合计 8,557,250，仅 XYZI 约 32.6 MiB），加载、内存与网格成本为固有增长，由离屏实测记录。
- 新 `.vox` 若缺配对 meta 会在启动即失败，而不是被静默按 1 米/格加载；
  非坦克资产（爆炸、混凝土墩）保持 0.1 配置。
- 未来若做细网格美术作者化，可改生成流程直接产出 0.02 契约，不在本次扩展。
