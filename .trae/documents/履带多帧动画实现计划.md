# 履带多帧动画实现计划（方案 A：相位变体 + 显隐切换）

## Summary

为玩家坦克实现履带滚动动画：程序化重写 `default.vox`，把履带拆成左右各 3 个相位变体子节点（带棱角凸齿），运行时按左右履带线速度积分里程、切换变体可见性。原地转向时左右履带差速滚动（一侧前进一侧倒转）。

## 现状分析（已探明的事实）

- [default.vox](file:///e:/Workspace/Code/Rust/Tanker/assets/tank/player/default/default.vox)：32×24×15 体素（×0.1m = `TANK_SIZE (3.2, 1.5, 2.4)`），4761 体素，**单 shape 整体模型**（场景图仅 1 个名为 `tank` 的节点），无独立履带节点。
- 履带 = 两侧实心条：**y0-3（左）/ y20-23（右）**，x0-29（长 30），z0-5（高 6），全部 idx4（深灰 RGB 38,40,38）+ idx5（浅灰 RGB 78,80,76）。侧面现有周期 5（3 浅 2 深）的条带纹理，几何上完全光滑——"平滑感"的来源。
- 车头 = 模型局部 **−X**（[driving.rs#L87](file:///e:/Workspace/Code/Rust/Tanker/src/driving.rs#L87)）；相机为车尾上方 15° 俯视（[driving.rs#L120-L126](file:///e:/Workspace/Code/Rust/Tanker/src/driving.rs#L120-L126)），履带外侧面 + 顶面是主要可见面。
- bevy_vox_scene 0.22 会把 vox 节点名写入 Bevy `Name` 组件（缓存源码 parse_scene.rs:171/209）→ 加载后可按名字找子实体。
- `TurnRate`（转向角速度资源）为 driving 模块私有；`drive_tank` 在 `FixedPostUpdate` 写 `LinearVelocity`。
- 敌人模型（tank/enemy/default/default.vox）不含 `track` 字样 → 全局 Name 匹配不会误伤。
- `TANK_SIZE` 的 5 处引用全部通过常量计算（碰撞体/测试），改常量本身即可自动适配。

## 变更内容

### 1. 新增脚本 `.scratch/track-anim/gen_vox.rs`（rustc 单文件，纯 std）

一次性生成脚本：读 `default.vox` → 备份 → 重写为多节点场景图 → 覆盖写回。

**解析**：VOX magic/版本校验 → MAIN children 遍历 → 收集 SIZE、XYZI（4761 体素）、RGBA 调色板、MATL 材质块（原字节保留）、原场景图 chunk 布局（作为输出格式参照）。

**分类与变换**：
- 履带体素：y ∈ [0,3] ∪ [20,23]；车体体素：y ∈ [4,19]。
- 全部体素 y+1；新 SIZE y 24→26。新履带区：左 y1-4、右 y21-24。

**生成 7 个 model**：
- `body`：车体体素（y+1 后原样）。
- 每侧 `side ∈ {l,r}`、相位 `p ∈ {0,1,2}` 共 6 个变体：
  - 履带主体：原履带体素，外侧面层（左 y=1 / 右 y=24）颜色重排为周期 3 图案：`(x + p) % 3 == 0` → idx5，否则 idx4（替换原周期 5 纹理）。
  - 侧面凸齿（新增体素）：外侧面外凸 1 格（左 y=0 / 右 y=25），x 满足 `(x + p) % 3 == 0`，z0-5 全高，颜色 idx5。
  - 顶面凸齿（新增体素）：z=6（z 上方有余量，无需扩 z），x 同侧面齿位置，跨履带全宽（y1-4 / y21-24），颜色 idx5。
  - 侧面齿与顶面齿在 x 上对齐，构成完整"履带板"单元。

**输出场景图**（多 model + 命名节点，nTRN/nGRP/nSHP 结构照原文件模式构造）：

```
MAIN → nTRN(root) → nGRP → ┬ nTRN "body"        → nSHP(model 0)
                           ├ nTRN "track_l_0"   → nSHP(model 1)
                           ├ nTRN "track_l_1"   → nSHP(model 2)
                           ├ nTRN "track_l_2"   → nSHP(model 3)
                           ├ nTRN "track_r_0"   → nSHP(model 4)
                           ├ nTRN "track_r_1"   → nSHP(model 5)
                           └ nTRN "track_r_2"   → nSHP(model 6)
```

**备份**：原文件复制到 `.scratch/track-anim/default.orig.vox` 后再覆盖。
**自校验**：打印各 model 体素数与总数（4761 + 新增齿数），供人工核对。

### 2. 新增 `src/track.rs`（运行时驱动）

```rust
pub(crate) struct TrackAnimationPlugin;
```

- 常量：`TRACK_PITCH: f32 = 0.3`（齿距 3 格 × 0.1m）、`TRACK_PHASES: i64 = 3`、`HALF_TRACK_WIDTH: f32 = 1.3`（扩容后 2.6/2）。
- `TrackAnim` 组件（挂玩家 Tank 根）：`left: [Entity; 3]`、`right: [Entity; 3]`、`dist: [f32; 2]`（带符号里程）、`phase: [i64; 2]`（当前相位，避免每帧写组件）。
- 系统 `link_tracks`（Update 轮询）：
  - Query `&Name` 过滤 `track_l_0`…`track_r_2` 六个名字（敌人模型无此名，安全；单玩家坦克前提，加 `ponytail:` 注释标注多坦克时的升级路径）。
  - 齐了 6 个后：对 Tank 根插入 `TrackAnim`，并立即隐藏相位 1/2（`Visibility::Hidden`），只留相位 0——防止初始 6 层叠加渲染 z-fighting。
  - 已有 `TrackAnim` 则跳过（轮询退出）。
- 系统 `advance_track_phases`（PostUpdate，`follow_tank` 同阶段，读 `drive_tank` 最新结果）：
  - 差速公式（向量法，免疫左右符号错误）：每侧履带接触点速度 `v_side = (linear + ω⃗ × r_side) · forward`，其中 `ω⃗ = (0, turn_rate, 0)`，`r_side = rotation * (0, 0, ∓HALF_TRACK_WIDTH)`（局部 ±Z 是车体两侧，宽在 z），`forward = rotation * Vec3::NEG_X`。两侧与视觉左右的对应以运行画面验证为准。
  - `dist[i] += v_side × dt`；`ph = (dist / TRACK_PITCH) as i64` 后 `rem_euclid(3)`。
  - 相位变化时才写 `Visibility`（`Visible`/`Hidden`）。
- **单测**（ponytail 规则，纯逻辑 assert，不依赖渲染）：
  - 相位推进：`phase(0.0)==0`、`phase(0.31)==1`、`phase(-0.05)==2`（倒车相位回退）、`phase(0.9)==0`（周期回绕）。
  - 差速符号：ω>0（左转）时，右履带速度 > 左履带速度；直线时两侧相等。

## 假设与风险

- **vox 场景图重写是最大风险**：nTRN/nGRP/nSHP 字段布局以原文件字节为模板照抄；生成后 `cargo run` 看 "vox 场景加载完成" 日志即证明解析通过；失败时从 `.scratch/track-anim/default.orig.vox` 还原。
- 变体实体的 `Visibility` 控制 nTRN 节点实体，Bevy 的可见性传播会隐藏整棵子树（mesh 在其子级）。
- 齿频验算：6 m/s ÷ 0.3 m = 20 齿/s × 3 相位 = 60 相位切换/s ≈ 60fps 每帧一切换。体素风格可接受；若观感闪烁，调大 `TRACK_PITCH`（无需改模型，只是滚动变慢）。
- 脚本放 `.scratch/`（git 忽略，本地保留），不污染工程构建。
- firing.rs 未引用 `TANK_SIZE`，炮口不受扩容影响。

## 实施顺序

1. 写脚本 → 备份原模型 → 生成新 default.vox → `cargo run` 验证加载日志与模型外观（齿清晰、无叠加闪烁）。

4. `cargo run` 画面验证四象限：前进 / 倒车 / 原地左转 / 原地右转，履带滚动方向正确、静止时不动。
