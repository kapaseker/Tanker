# 05: 返工整车集成、用户验收与长期依据

**What to build:** 将获认可样板方向下的全车细节、轮带和呈现方案集成，交付完整真实引擎对照及技术证据。用户明确认可最终实际版本后，才把车型记录更新为最终美术验收通过。

**Blocked by:** 02 — 轮组与履带的厚度及动态层次；03 — 车体、装甲、附件与炮管整体细化；04 — 经实验验证的光照方案与实际入口落地。

**Status:** claimed

依据：上级目录返工规格与获认可样板记录。本票验证最终组合，不承担前面各票应做而未做的首轮测试；旧系列关闭状态不能替代新证据。

- [ ] 按返工规格逐项核对炮塔、车体、附件、轮组、履带、炮管和配色/材料，集成后仍达到获认可样板的层次；结构连接、轮带/裙板净空及炮口无回归。
- [ ] 真实尺度、0.02 米作者化、完整视觉附件范围、共同原点与 0.1 米主要碰撞分别验证；敌方、既有弹丸、驾驶和战斗规则保持，实例清理完整。
- [ ] 确定性重生成、发布检查、相关生成器/资源测试、cargo check 和 Cargo 测试套件通过；无关既有失败保留并说明，相关失败不能跳过或降低断言。
- [ ] 最终 scene、wheels、drive、combat 和受影响 gallery/detail 离屏通过，检查后端、真实资源、GPU 管线、退出码、报告和图片保存；遵守 180 秒预算，不自动回退可见窗口。
- [ ] 实际读取前进、倒车、左右原地转向、停车、开火、命中及销毁关键帧，确认轴心稳定、相位闭环、无明显穿插及相关实例全部清理。
- [ ] 最终游戏、画廊、详情使用同一真实资源，初始取景及完整旋转包络不裁切炮管/附件；正常镜头看得到主要结构，不只靠近景证明完成度。
- [ ] 提供同条件旧/新模型、已选参考图与获认可样板的前侧上方、正侧后、正常游戏视角和必要部件近景；注明实车纠正、体素简化及尚存差异，不能以新 AI 图代替实际渲染。
- [ ] 在同机同配置比较旧基线、样板和最终资产体积、体素量、加载就绪时间及可获得的网格/内存统计；不可测项如实注明，不用文件大小冒充内存或虚构性能门槛。
- [ ] 明显卡顿、资源耗尽、错误或相关验证缺失必须修复或报告阻碍；技术通过与美术待确认分别报告，不能自动将两者合并为“验收通过”。
- [ ] 展示最终实际图像/资产版本并记录用户明确确认；最终结果与样板明显变化时重新展示。没有最终确认，本票不标为 resolved，车型目录保持待美术验收；用户拒绝则继续关联返工，不以旧样板确认代替。
- [ ] 将关键参考图、获认可样板、最终关键对照与版本、设计取舍和验收边界保存为可随 Git 共享的长期依据；大量本机临时日志可保留本地，旧技术历史不删除。
- [ ] 通过后同步车型目录、模型/尺寸说明和验收结论，进行 retro：可自动判定的画布/附件/安装问题落实为检查；形态质量与用户确认落实为美术验收规则，避免再次以零件存在代替达标。
