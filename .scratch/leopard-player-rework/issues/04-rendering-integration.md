# 04: 经实验验证的光照方案与实际入口落地

**What to build:** 依据样板的受控光照对照，把得到证据支持的呈现方案用于实际游戏或模型预览，验证效果与影响；若现有方案已足够，则保留现状并交付明确的实验结论，不为工单强行改灯光。

**Blocked by:** 01 — 真实引擎车体与炮塔视觉样板（必须包含用户明确确认和受控光照实验记录）。

**Status:** ready-for-agent

依据：上级目录返工规格及 01 样板。不是重新做造型的替代方案，不以灯光隐藏仍未解决的几何问题。

- [ ] 复核样板实验相机、投影、曝光、背景和几何版本，只有灯光/环境呈现目标变量改变；变量混杂时先修正实验，不能据无效对照决定方案。
- [ ] 明确是否需要正式调整及其作用域（预览或实际场景），说明改善点、代价与保留限制；无收益或缺证据则保持原配置并记录，不默认添加方向光或重配全局亮度。
- [ ] 若调整，沿用现有材质和渲染能力，以最小改动落地；不新增通用材质系统、依赖、渲染框架或整车专用假场景。
- [ ] 同一真实模型在默认游戏镜头、预览和近景中结构与材料可读，避免过曝、整车发浅或暗部遮盖；保留旧/候选方案同几何对照。
- [ ] 若触及公共或全局光照，覆盖实际游戏、敌车和其它受影响展示资产；不只在专用样板截图下验证，不顺带重做敌方或 UI。
- [ ] game/gallery/detail 使用相同交付资产，完整附件包络与取景正确；若必须调整取景，保留原布局、操作和 body 根旋转，并遵循既有设计规范。
- [ ] 修改 Rust 后 cargo check 和相关回归通过，相关 scene、gallery/detail 等离屏通过并实际读取帧；按真实影响扩大验证，遵守 180 秒预算。
- [ ] 记录实际采用的呈现方案、样板版本、修改或不修改的理由及加载/网格成本；最终集成票仍需使用 02、03 最终资产复核，不能把本票样板实验当成最终全车验证。
