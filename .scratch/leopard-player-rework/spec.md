# 豹 2A6 玩家模型外观返工规格

Status: ready-for-agent

日期：2026-10-29

## Problem Statement

玩家对比选定的第一张豹 2 概念效果图与实际游戏模型后，明确表示不能接受当前外观。现有模型完成了真实尺度、七负重轮、三包装配和战斗集成，但炮塔呈连续大斜坡，装甲分层不清；车顶设备被压成薄片，轮胎、轮毂和履带缺乏厚度与材料区分；整车呈大块盒体拼装效果，明显未达到所选参考图的结构层次和完成度。

旧验收以尺寸、零件存在、资源加载、动画和测试通过为主要依据，没有充分评价形态质量。技术测试与历史执行记录保留，不能继续表示用户认可最终美术效果。当前型号目录和验收记录已更正为美术返工状态。

## Solution

保持豹 2A6、L55、真实整车比例及现有玩法基准，重做影响观感的几何结构和材料层次。先在真实游戏引擎中交付车体与炮塔视觉样板，提供同视点对照和最小光照实验，供用户确认实际效果。样板得到用户明确确认后，再按其质量完成轮带、裙板、炮管及附件，并完成技术、美术两条独立验收。

现有真实资源、作者源和离屏验证入口是执行基础。首个制作交付是可重建、可加载的引擎渲染样板，不再用新 AI 图或网页模拟图代表实际完成度。

## User Stories

1. 作为玩家，我希望实际模型达到所选参考图的结构层次，以便最终看到的坦克符合预期。
2. 作为玩家，我希望先看到实际引擎样板，以便在全车细化前判断制作方向。
3. 作为玩家，我希望样板明确说明完成和未完成部分，以便不会把阶段成果误认为最终交付。
4. 作为玩家，我希望炮塔前楔装甲、主体、炮盾和后舱可以分别辨认，以便摆脱整块斜坡的观感。
5. 作为玩家，我希望前楔装甲有厚度、边缘和接合关系，以便轮廓具有可信的重量感。
6. 作为玩家，我希望车首、甲板、挡泥板、灯具和裙板形成自然层次，以便车体不再像盒子简单叠放。
7. 作为玩家，我希望观瞄、舱盖和机枪有合理高度与体积，以便车顶不再呈几个薄片。
8. 作为玩家，我希望天线和附件依据实车比例制作，以便画布限制不会改变其外形。
9. 作为玩家，我希望轮胎、轮毂、端轮和履带板有厚度与材质区别，以便行走机构呈现重量感。
10. 作为玩家，我希望轮间透空和转动净空保持正确，以便细化不会造成穿插。
11. 作为玩家，我希望炮管根部、抽烟器、管身和炮口粗细分段清楚，以便长炮管具有结构辨识度。
12. 作为玩家，我希望橄榄绿装甲与深灰橡胶、履带清楚区分，以便模型不再整体发浅。
13. 作为玩家，我希望正常游戏镜头下能读懂主要结构，以便近景细节不会掩盖远看轮廓的问题。
14. 作为玩家，我希望用相同视点观察修改前后，以便判断几何变化而非取景差异。
15. 作为玩家，我希望看到同一几何的光照对照，以便知道改善来自模型还是渲染。
16. 作为玩家，我希望模型在已有光照下也结构清楚，以便不会靠阴影隐藏问题。
17. 作为玩家，我希望真实尺寸、主要车体碰撞及原有操作保持一致，以便返工不改变游戏规则。
18. 作为玩家，我希望游戏、画廊和详情都呈现同一套模型，以便样板品质能够实际落地。
19. 作为玩家，我希望外观由我确认后才标记美术验收通过，以便测试通过不会替代我的判断。
20. 作为维护者，我希望样板及最终资源可确定性重生成，以便作者源与交付资产一致。
21. 作为维护者，我希望视觉画布与碰撞边界分别维护，以便合理附件不会迫使物理框变大。
22. 作为维护者，我希望每个阶段有相关测试、关键帧和成本记录，以便逐步改进而不累积回归。
23. 作为维护者，我希望旧证据与新返工记录分开保存，以便设计变更和验收结论可追溯。

## Implementation Decisions

### 1. 既有约束与范围

- 现实型号仍为豹 2A6，L55 长炮管，保留车体 anvil、炮管 lance、履带 cleat 三包身份和现有附属弹丸；炮塔仍包含在 body 中。
- 美术使用 0.02 米资产格，运行时参考格和 0.1 米主要车体简化圆角碰撞继续分别维护。沿用既有资产分包、模块依赖和逐部件 VOX/meta 配对保护。
- 已有尺寸表与可靠的对应型号资料约束真实比例；第一张概念图约束美术层次。图中不准确的轮数、结构或比例需用实车资料纠正并说明，不逐像素复刻错误。
- 维持每侧七个负重轮与两个端轮、现有驾驶、转向、重力、生命、弹速、射速、伤害、射程、弹丸形态和扫掠规则。本轮不默认重新制作弹丸。
- 非炮管车长、整车宽度、炮向前全长和主体顶高以已有来源/量化口径为基线。可靠资料驱动的局部修正须同步尺寸表、作者源与必要安装契约，不以扩大整车或非统一缩放制造厚重感。

### 2. 可审阅的视觉目标

| 区域 | 必须达到的形态 | 不满足目标的表现 |
|---|---|---|
| 炮塔 | 前楔附加装甲、主体、炮盾及后舱在前侧和侧视图中清楚分区；有可读的厚度、折面、边缘和接合 | 连续大斜坡、整块削角盒体，或只画一条色带表示装甲分区 |
| 车体 | 倾斜车首、甲板、挡泥板、灯具、侧装甲和裙板结构相接；板缝与边缘有实际几何层次 | 平面盒体堆叠、用碎色替代形体、灯具仅为无轮廓色点 |
| 车顶附件 | 舱盖、观瞄、机枪等有各自可辨体积和高度关系，天线比例合理 | 统一压进炮塔顶上 6 厘米内、为了复用画布而压扁附件 |
| 轮组 | 轮胎、轮毂、中心盖和端轮有厚度与前后层次，深色轮胎与车身区分 | 同厚度浅色圆片、所有轮面处于同一平面 |
| 履带 | 履带板厚度、节距和端部包覆可读，轮带关系合理，保留闭环运动 | 单薄线框或悬浮横齿，仅靠颜色表示板厚 |
| 炮管 | 根部、炮盾接合、抽烟器、管身和炮口比例合理，在整车视角可辨粗细变化 | 单一细杆、细节虽存在但比例小到不能形成主要结构 |
| 配色与材料 | 橄榄绿装甲、深灰橡胶/履带、局部暗缝和少量磨损相互支撑 | 整车发浅、轮胎与装甲难分，靠密集噪点冒充细节 |

- 正常游戏镜头考察主要轮廓、分区和材料关系；近景考察附件、接缝和轮带形态。亚体素螺栓和划痕可简化，不能据此简化主要机械结构。
- 上表是实际渲染的美术检查清单，不能通过自动判定“有某个部件”、体素计数或测试退出码代替。

### 3. 视觉画布与物理独立

- 解除旧 2.70 米统一画布对附件高度的限制。按完整可见几何扩展画布或已有场景布局；显式区分主体顶高、附件范围、视觉画布、安装根与主要碰撞边界。
- 扩展视觉画布不直接改变主要车体碰撞、离地位置、轮轴或炮轴。维护共同原点和各包安装变换，画廊仍绕 body 根旋转，不用含炮管包围盒重新居中。
- 主体碰撞继续按既有 0.1 米向外量化和圆角规则维护，炮管与细小附件不单独加碰撞。细小附件的最高点不用于抬高碰撞框。
- 更新与旧视觉高度强耦合的作者源、边界检查、分块、安装、取景和尺寸显示，不删除必要的越界与发布保护。

### 4. 第一张实施票交视觉样板

- 修改前保留当前资源、生成契约、版本与同视点图片基线，复用现有正/侧/后和前侧上方入口。
- 样板优先修复车体与炮塔大形、前楔厚度、炮盾接合、后舱和车首层次，并恢复关键车顶附件合理体积。允许暂用已有轮带、弹丸和次要装饰，但对未返工部分明确标记。
- 样板必须来自可重复生成的实际 VOX、真实加载和 Bevy 离屏渲染，能够在现有组装中运行。需要的作者源和验证入口调整属于该票，不先发布一堆看不到结果的基础票。
- 首先在已有光照下展示样板，再以相同几何、相机和曝光等条件做最小灯光对照；准确记录改变的变量，不把同时改变模型与灯光的两张图当作光照实验。
- 样板包包含现状与改进的前侧上方、侧视、正常游戏镜头，以及必要的炮塔/附件近景；保持视点一致、投影一致、画面占比可比，标注尽量不遮挡待比较区域。
- 技术检查通过且图像齐全表示“样板可审阅”，不等于“样板获认可”。记录用户对具体样板版本的明确确认后，才进入依赖该视觉方向的全车细化。
- 用户未确认时只允许继续样板修订、独立调查和必要验证；先前“未回答采用推荐选项”不替代对实际视觉产物的确认。

### 5. 样板后完成全车

- 根据获认可的样板完善轮胎/轮毂和端轮厚度、履带板与包覆、裙板、格栅、前灯、装甲接缝、全部约定附件和炮管分段。
- 以几何、分区和局部材料关系建立细节层次，复用既有资产能力；不默认引入新材质系统、渲染框架、依赖或通用编辑器。
- 样板后的工单按可运行、可查看、可回归的整段结果拆分。依赖用户样板结论的具体细化参数，在样板确认后冻结；提前拆票时须显式写出该阻塞条件，不能将尚未确定内容当作可无条件执行。
- 每个切片同步作者源、交付资产、相关契约/文档、测试和关键帧，保持敌方原有模型与行为。旧 01–06 的关闭记录不作为新返工票已经完成的证据。

### 6. 光照与实际入口

- 当前环境光/环境贴图配置与模型几何分别分析；没有在同条件下实验前，不宣称某个亮度或添加方向光必然解决观感问题。
- 灯光对照保持为局部、可识别的离屏实验。正式采用时明确作用域，优先解决被证明存在的问题，不默认更改全局游戏光照。
- 若改实际游戏或公共预览光照，同步回归受影响场景、敌车和其它展示资产。不能只在专用摄影棚中看起来好看而不检查默认游戏镜头。
- 画廊和详情复用同一玩家成品。必要时适配视觉包围盒、完整旋转包络、取景和实际尺寸显示；保留既有页面布局、交互和设计规范。

### 7. 验收与记录

- 技术验收和美术验收分别报告：技术包括生成、装配、尺寸、碰撞、动画、战斗、资源清理和运行成本；美术包括上表逐项对照、样板确认与最终用户确认。
- 旧执行结果保留为历史技术证据；长期车型目录和模型说明保持“返工/待美术验收”，直到用户确认最终实际画面。最终交付与样板明显变化时重新展示，不沿用旧样板认可。
- 保留参考图、获认可样板及版本、关键对照图和长期结论，确保后续会话能辨认视觉标准。临时日志和大量动态帧可留本机，但核心视觉依据不能只存在于会话或忽略目录。
- 收束时进行 retro：将可判定的附件包络、原点和安装错误补为回归；将形态质量、实际画面对照和用户确认要求维护到模型验收规则，避免把零件存在当成完成度。

## Testing Decisions

### 验证边界

沿用返工计划已经提出的边界：以“作者源生成交付资产 → 真实加载和装配 → 实际游戏与预览离屏输出”为主要验收，优先复用现有入口。生成与几何检查只补充场景图不能稳定检测的约束；不建立平行的假场景或通用测试框架。

同条件图像对照回答几何/光照差异，用户对实际版本的确认回答美术是否达标。技术测试与截图自动检查不能回答审美接受度。

### 每个实现切片

- 修改 Rust 后 cargo check 必须通过，执行相关生成、发布、资源和运行行为测试；新逻辑保留有意义的回归，已有无关失败须单独说明。
- 检查 0.02 米元数据、命名节点、分块边界与接缝、完整附件包络、共同原点、视觉/碰撞独立性、轮轴和炮口；针对画布扩展补充安装不漂移、物理框不随附件扩高的验证。
- 检查模式不修改交付资产，确定性生成与交付匹配，保持逐部件配对保护；不以手改成品或降低验证绕过重生成。
- 对真实资源测量尺寸与安装结果，不用内部函数形状或旧字节快照限制合法造型改变。有关尺寸改变同步明确来源和量化误差。
- 相关离屏场景必须退出成功、报告通过、所需图片保存完整，并实际读取关键帧；样板阶段也不能省略此项。失败不自动改用可见窗口。

### 静态与动态验收

- scene/wheels 提供整车与部件视图，gallery/detail 验证默认取景、完整旋转包络、尺寸和浏览表现。复用已有入口，不足时仅扩充对应观察点。
- 对比顺序：旧几何与新几何在现有光照下同视点比较；新几何在现有光照与候选光照下同视点比较。记录相机、投影、曝光、背景及光照变量，避免混淆。
- 保留正常游戏镜头，以及整车前侧上方、正/侧/后、炮塔装甲、车顶附件、轮带和炮管必要近景。正侧尺寸用于验证比例，近景细节不能替代整车观感。
- wheels 动态覆盖前进、倒车、左右原地转向及停车，检查轮带完整包络、旋转方向、相位闭环、轴心稳定、裙板净空及新增厚度是否穿插。
- drive/combat 回归既有驾驶、正确炮口、扫掠命中、爆炸、销毁与实例清理；不为返工改变玩法断言。敌车保留独立尺寸与原有行为。
- 最终执行 cargo check、Cargo 测试套件及相关生成/资源/发布检查；完成 scene、wheels、drive、combat 及受影响 gallery/detail。遵守当前启动后 180 秒预算，不放宽超时或降低断言取得通过。

### 性能与完成标准

- 在同机同配置下比较返工前后体素/资产体积、加载就绪时间及可获取的网格和内存统计。样板和最终各记录一次，图像质量改善不能掩盖明显资源耗尽、加载失败或卡顿。
- 区分实测与不可获取指标，不用文件大小代表内存，不虚构新的 FPS、像素相似度或内存门槛；环境差异与测量限制必须注明。
- 样板阶段：上表中的炮塔/车体/附件主要缺陷得到改善，实际引擎图像与技术证据完整，用户明确确认该版本。若被拒绝，继续样板而不展开依赖其方向的全车细化。
- 最终阶段：技术回归通过，全部约定部位达到获认可样板的层次，真实游戏/预览图与结构检查完整，用户确认最终实际效果，长期文档状态同步。未满足任一项不得声称最终美术验收通过。

## Out of Scope

- 改变现实参考型号、加入 A7/A8 装备、增加其它坦克或涂装系统。
- 重做弹丸美术、弹种选择、真实弹道/装甲模拟、玩法平衡和敌方美术。
- 独立炮塔转向、炮管俯仰、悬挂模拟、装填与抛壳动画、逐体素破坏。
- 逐装甲板精细碰撞、炮管或小附件碰撞、地形与无关碰撞修复。
- 新 AI 效果图替代实际样板、网页 UI 原型、独立假渲染器或通用模型编辑器。
- 未经验证直接重配全局灯光、引擎/插件升级、新通用材质框架及无关 UI 重设计。
- 可见窗口、真实键鼠、焦点及显示缩放验证；需要时另行说明原因并取得同意。

## Further Notes
