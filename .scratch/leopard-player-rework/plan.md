# 豹 2 玩家模型外观返工计划

日期：2026-10-29

## 起点与目标

用户对比已选概念图和实际模型后明确表示不能接受当前外观。旧 01–06 的技术测试和执行记录保留，但不能再据此声称最终美术验收通过。新返工单独组织，不覆盖旧验收证据。

目标仍为豹 2A6 真实比例、0.02 米细体素、0.1 米主要车体简化碰撞、现有玩法与三包结构。第一张概念图指导美术完成度，可靠实车资料约束结构；不以逐像素复刻或实车制造精度作为承诺。

## ask-matt 路线

沿用已确认需求，集中补齐视觉验收定义 → to-spec / to-tickets 固定返工范围 → 先实施一张真实引擎视觉样板票 → 用户确认样板 → 逐票 implement 完成其余外观 → 技术与美术分别验收 → retro 收束失败原因。

本计划不要求重做先前需求采访。prototype 技能现有分支主要面向逻辑 HTML 与网页 UI 变体，本工程需要复用真实 VOX 加载、场景和离屏渲染；采用受限的实际模型样板，不另建网页、假渲染或新一轮 AI 效果图。

## 工作顺序与完成条件

### A. 固定对照与返工验收条件

- 保存当前模型、所选概念图及其尺寸/生成契约基线，记录版本。现有正侧后视图入口优先复用。
- 对照采用相同视角和接近的画面占比；提供前侧上方、侧面、正常游戏镜头及必要近景。背景、标注和取景不同不能替代模型判断。
- 列出待修复结构：分离可读的炮塔前楔装甲/主体/炮盾、车首及侧裙层次、合理高度车顶设备、有厚度的轮胎轮毂与履带、炮管粗细分段。
- 明确视觉画布、附件范围、主体碰撞三者独立；禁止为维持 2.70 米旧画布而把观瞄、机枪和天线压扁。
- 完成条件：差异清单和对照条件落到返工规格；不将“部件存在”作为“形态达标”。

### B. 先交付真实引擎视觉样板（首张实现票）

- 优先重做前侧视图中决定整车观感的车体与炮塔大形：前楔装甲的分块厚度、炮盾接合、炮塔侧面/后舱及车首分层。
- 扩展视觉画布或场景布局，使车顶观瞄、舱盖、机枪等有合理外形与高度；保留主要车体碰撞方式，不机械放大物理框。
- 保留现有履带、弹丸和战斗规则作为阶段部件，清楚标注尚未返工处。样板不是全车最终完成。
- 首先在现有光照下观察模型形态。再使用同一几何做最小离屏灯光对照，区分几何改进与光照贡献；灯光实验不直接全局修改游戏表现。
- 生成流程必须能重建样板；涉及 Rust 时 cargo check 通过，尺寸/装配/炮口/资源检查和相关离屏验证仍需执行。
- 完成条件：真实引擎正侧/前侧对照、正常镜头及近景可审阅，主要造型缺陷得到解决。用户实际确认视觉样板后才进入全车细化；未得到确认只做独立检查与样板修订，不默认视为认可。

### C. 完成全车结构与材质层次

- 在获认可的大形基础上完成七负重轮轮胎/轮毂厚度、端轮、履带板包覆和板间层次，保留正确动画与净空。
- 完善分段裙板、装甲接缝、甲板格栅、前灯、合理车顶附件及炮管根部/抽烟器/炮口。
- 使用主色、暗色和局部材质对比组织结构，避免靠增加碎色或单纯堆体素冒充细节。
- 每个可运行切片带生成、装配、相关行为测试及静动态关键帧，不把全部验证推到末尾。
- 本轮不默认重做弹丸、敌车、地形和玩法；发现真实回归时修复关联问题。
- 完成条件：所有约定部件达到样板的视觉质量，动画无穿插，重生成一致，相关测试和关键帧检查通过。

### D. 渲染适配与最终验收

- 依据样板实验决定是否调整模型预览或实际场景光照；需分清局部预览与全局影响，若改动全局光照必须回归实际游戏及敌方场景。
- 不靠强阴影遮盖错误几何。保留现有光照与改进光照同几何对照，以便评估收益和代价。
- 技术验收：cargo check/相关测试、生成一致性、碰撞与炮口、行驶和清理、scene/wheels/drive/combat 及受影响 gallery/detail，检查报告和实际关键帧。遵守当前 180 秒超时，不降低门槛。
- 美术验收：与选定参考图及获认可样板逐项对照，说明实车纠正和体素简化；用户确认实际结果后才将车型目录标为美术已验收。
- 成本记录：同机对比加载就绪时间、资产/网格开销及可获取的内存数据，未测项目如实注明。
- 完成条件：技术验证通过且美术得到用户确认，长期模型文档与车型目录同步，资料/平台限制记录清楚。

## 拆票原则

后续正式工单以本计划和已有车型规格为依据，每票具备实际可看的结果和验收证据。第一张实施票必须交视觉样板；依赖样板结论的全车细节票在样板确认后再冻结具体实现范围，避免再次一次做完后才发现方向偏差。

## 流程复盘

最终用 retro 检查为何“具备零件”和“通过技术测试”替代了外观质量判断；将可自动检查的尺寸/附件包络交给回归测试，将视觉结构判断和用户确认要求写入模型验收说明。既有测试通过记录不删除，也不继续用于声称被拒绝的外观已经获认可。

本轮仅制定计划与修正状态，尚未发布新规格/工单、制作样板或修改游戏资源。
